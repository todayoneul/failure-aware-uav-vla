# Phase 2 첫 데모 계획: 비슷한 차 사이에서 지정한 차 따라가기

이 문서는 Phase 2의 첫 데모를 무엇으로, 어떻게 만들고, 어떻게 채점할지 정한다. 2026-11-13에 사용자와 다섯 항목(범위, 인식 방법, 추종 제어, 화면, 채점)을 차례로 정했다. 아직 구현하지 않았다. 실행 환경은 [phase2_setup](phase2_setup.md)에 있다.

## 1. 목표와 범위

**목표.** 문장으로 지정한 차 한 대를 찾아 락온하고, 차 뒤 20m, 위 15m를 유지하며 따라간다. 목표 근처에 같은 차종·같은 색의 차가 2–3대 있어도 다른 차로 바뀌지 않아야 한다. 이것은 Phase 2의 핵심 질문("비슷한 차가 많고 가려짐이 있어도 지정한 그 차를 놓치지 않는가")의 앞부분이다.

**범위 밖.** 다음은 첫 데모에서 다루지 않고 5절로 넘긴다.

- 가려졌다 다시 나온 목표를 다시 잡기
- 화면 밖에 있는 목표 수색
- 실제 드론 3D 모델
- 학습한 추종 정책(VLA)

## 2. 구성

```text
시작 (1회)
  영상 → 차량 탐지 → 후보마다 번호 → VLM(문장 + 번호 붙은 영상) → 목표 번호 → 목표 트랙

매 tick (20Hz)
  영상 → 차량 탐지 → 다중 객체 추적(움직임 예측, 드론 자기 움직임 보정) → 목표 트랙의 상자
       → 상자 아래 가운데를 땅에 투영 → Kalman filter(목표 위치, 속도, 진행 방향)
       → 목표 지점(진행 방향 뒤 20m, 위 15m) → 제한을 지키며 드론 이동 → 카메라는 목표를 바라봄
```

### 2.1 처음 지정

- **후보 표시.** 차량 탐지기로 후보 상자를 얻고, 상자마다 번호를 붙인 영상을 VLM에 보여 준다. VLM은 문장에 맞는 번호 하나를 답한다.
- **VLM.** 2–4B 크기의 소형 VLM을 4-bit로 쓴다(메모리 약 3GB). 구체적인 모델은 구현 6단계(4절)에서 후보를 재 보고 고른다.
- **문장.** 차종, 색, 위치를 함께 쓴다. 예: "follow the white SUV in the left lane", "왼쪽 차선의 흰색 SUV를 따라가".
  - 비슷한 차가 처음부터 함께 보일 수 있으므로, 차종과 색만으로는 한 대로 정해지지 않을 수 있다.
  - 그래서 시험 문장에는 그 시점에 목표 한 대로 정해지는 위치 표현(차선, 앞뒤 순서)을 넣는다.
- **문장 자동 생성.** 시험 문장은 simulator 정답(blueprint, 색, 차선, 순서)에서 만든다.
  - 차종 이름(SUV, sedan, hatchback, pickup, van 등)은 car blueprint 23개에 손으로 붙인 표로 정한다.
  - 색 이름은 blueprint의 RGB 값에서 정한다.

### 2.2 추적

- **탐지기와 추적기.** 매 tick YOLO 계열 차량 탐지기(1GB 이하)를 돌리고, 다중 객체 추적기(ByteTrack 또는 BoT-SORT)로 상자를 트랙으로 이어 붙인다.
- **비슷한 차 구분.** 비슷한 차는 겉모습이 같으므로 생김새가 아닌 움직임이 이어지는지가 주된 단서다.
- **추적을 돕는 정보.** 드론 자신의 움직임은 알고 있으므로 카메라가 움직인 만큼 보정한다. 2.3의 Kalman 예측(목표가 다음 tick에 있을 곳)도 추적기에 넘긴다.

### 2.3 추종 제어

- **위치 추정.** 목표 상자의 아래 가운데 점을, 드론 자세와 카메라 내부 값으로 땅 평면에 투영해 목표 위치를 얻는다. 실제 드론도 자기 위치와 자세(GPS, IMU)는 알고 있다는 가정이다.
- **상태 추정.** 등속 모델 Kalman filter로 위치, 속도, 진행 방향을 추정한다.
- **목표 지점.** 진행 방향 기준으로 차 뒤 20m, 위 15m.
- **드론 이동.** 비행 물리 없이 위치를 옮기되, 제한을 지킨다. 초기값은 최고 속도 20m/s, 가속도 4m/s², 방향 회전 60°/s다. 카메라는 추정한 목표를 바라본다.

### 2.4 화면

```text
+---------------------------+----------+
|                           | 3인칭    |
|  1인칭 (크게)             | 드론+차  |
|  [락온 상자] 22.4m        +----------+
|  "follow the white SUV"   | 지도     |
|                           | 위에서 봄 |
+---------------------------+----------+
```

- **1인칭.** 락온 상자, 목표 트랙 번호, 문장, 추정 거리를 표시한다.
- **3인칭.** 드론 뒤 위쪽 카메라 영상이다. 드론과 3인칭 카메라의 위치를 알고 있으므로, 프로펠러 4개짜리 드론 모양을 영상 위에 투영해 그린다.
  - 그리는 부분은 함수 하나로 분리해 둔다. 나중에 실제 3D 모델로 바꿀 때 그 함수만 바꾼다(5절).
  - 설치 확인 때 쓴 debug 상자는 모든 카메라에 찍히므로 쓰지 않는다.
- **위에서 본 지도.** simulator 정답으로 모든 차, 목표, 비슷한 차, 드론을 표시한다. OpenCV로 그리므로 GPU를 쓰지 않는다.

### 2.5 맵과 장면

- **simulator 설정.** Town05, 품질 Low, 동기 모드 20Hz.
- **차량.** 다른 차량 약 40대가 Traffic Manager로 자동 주행한다.
- **목표와 비슷한 차.** 목표 차와 같은 blueprint, 같은 색의 차 2–3대를 목표 근처에 둔다. 같은 방향의 옆 차선이나 앞뒤 spawn point를 쓴다. 비슷한 차도 자동 주행하므로 시험 중에 목표를 앞지르거나 나란히 달리게 된다.
- **메모리 예산.** simulator 약 2.5GB, 탐지기 1GB 이하, VLM 약 3GB. [phase2_setup](phase2_setup.md) 5절의 인식 모델 예산 약 6GB 안이다.

## 3. 채점

### 3.1 정답

매 tick simulator에서 다음을 얻는다([phase2_setup](phase2_setup.md) 4.4절).

- **목표의 화면 상자.** 3D bounding box를 1인칭 카메라에 투영한 상자.
- **보이는 pixel.** instance segmentation에서 각 pixel의 actor ID(G + 256·B).
- **위치.** 목표와 드론의 실제 위치.

### 3.2 지표와 합격선

**용어.**

- **추적 상자가 가리키는 차:** 추적 상자 안의 instance pixel 중 가장 많은 차량 ID.
- **바뀜:** 그 ID가 목표에서 다른 차로 바뀌어 5 tick(0.25초) 이상 이어진 경우. 차가 겹치는 순간의 짧은 흔들림은 세지 않는다.

**표 1. 지표와 합격선**

| 지표 | 정의 | 합격선 |
|---|---|---|
| 처음 지정 정확 | VLM이 고른 트랙이 목표 차인 시험의 비율 | 90% 이상 |
| 바뀜 없는 시험 | 바뀜이 한 번도 없는 시험의 비율 | 90% 이상 |
| 목표 유지 시간 | 목표가 화면에 보이는 tick 중, 추적 상자가 목표를 가리킨 tick의 비율 (전체 시험 합산) | 95% 이상 |
| 거리 오차 | 드론과 목표 지점(실제 목표 기준 뒤 20m, 위 15m) 사이 거리의 평균. 시작 후 5초는 제외 | 3m 이하 |

함께 기록하지만 합격선은 두지 않는 값:

- 목표가 비슷한 차와 10m 안에 있었던 시간
- 바뀜이 일어난 상대(비슷한 차인지, 다른 차인지)
- tick당 처리 시간
- GPU 메모리

### 3.3 시험 구성과 단계

- **시험 하나.** Town05의 시작 위치 하나와 seed 하나로 정해지고, 60초(1,200 tick) 동안 이어진다.
- **세 단계.** 시험은 pilot 3회, smoke 10회, 본평가 30회의 세 단계로 나눈다. 앞 단계를 통과해야 다음 단계로 간다.
- **본평가 시작 목록 봉인.** 본평가 30회의 시작 목록은 개발 전에 만들어 hash와 함께 봉인한다. 개발과 조정에는 쓰지 않는다.
- **재현성 확인.** 동기 모드와 Traffic Manager seed로 같은 시험이 똑같이 재현되는지 pilot에서 두 번 실행해 확인한다.

### 3.4 원인 나누기

실패가 어디서 났는지 알 수 있도록 세 구성을 같은 시험으로 돌린다. 합격선은 구성 3에 적용한다. 구성 1과 2는 진단용이다.

| 구성 | 처음 지정 | 추적 | 확인하는 것 |
|---|---|---|---|
| 1 | 정답 | 정답 상자 | 추종 제어만 |
| 2 | 정답 | 탐지기 + 추적기 | 추적 |
| 3 | VLM | 탐지기 + 추적기 | 전체 (데모) |

## 4. 구현 순서

각 단계가 끝나면 결과를 사용자와 확인하고 다음 단계로 간다.

1. **장면과 시험 목록.** Town05에 목표와 비슷한 차를 배치한다. 차종 이름 표와 문장 생성기를 만든다. pilot, smoke, 본평가 시작 목록을 만들고 본평가 목록은 봉인한다.
2. **드론 이동과 추종 제어 (구성 1).** 정답 위치로 따라가며 제한, 목표 지점, 카메라 조준을 맞춘다.
3. **화면.** 1인칭 표시, 3인칭 드론 그리기, 위에서 본 지도를 만든다.
4. **채점기.** 3.2절의 지표를 정답으로 계산한다.
5. **탐지기와 추적기 (구성 2).** 탐지기와 추적기 후보를 재고 고른다.
6. **VLM 지정 (구성 3).** VLM 후보를 메모리와 지연으로 재고 고른다.
7. **평가.** pilot, smoke, 본평가 순서로 진행한다.

필요한 Python 패키지(PyTorch, 탐지기, VLM)는 해당 단계에서 `pyproject.toml`에 더한다.

## 5. 이후 단계 (첫 데모 범위 밖)

- **가려짐 뒤 다시 잡기.** 다리 밑, 큰 차 뒤 같은 장면이 필요하므로 Town03 같은 맵에서 한다.
- **실제 드론 3D 모델.** CARLA 패키지에는 드론 모델이 없다(패키지 asset 12,904개에서 확인). 새 모델을 넣으려면 CARLA를 source에서 build해야 한다.
  - 공식 문서 기준 조건은 디스크 165GB, build 4시간 이상, Visual Studio 2022, CARLA 전용 Unreal Engine 4.26이다.
  - Unreal Engine 소스를 받으려면 GitHub 계정을 Epic 계정에 연결해야 한다.
  - 넣은 뒤에는 속도와 메모리를 다시 재고, 1인칭 카메라에 몸체가 찍히지 않게 위치를 맞춘다.
- **학습한 추종 정책(VLA).** 단순 제어와 같은 채점으로 비교한다.
- **화면 밖 목표 수색.**

## 6. 가정과 위험

| 항목 | 내용 | 확인 방법 |
|---|---|---|
| 땅 평면 가정 | Town05는 대체로 평평하지만 다리와 고가 구간에서는 투영이 틀릴 수 있다 | 구성 1–2에서 투영 위치와 정답 위치의 차이를 기록 |
| 나란히 달리는 비슷한 차 | 추적기가 가장 헷갈리기 쉬운 경우이자 이 데모가 보려는 경우다 | 바뀜 지표, 비슷한 차와 가까웠던 시간 |
| 문장의 모호함 | 처음 지정 시점에 비슷한 차가 같은 차선에 있으면 위치 표현으로도 한 대로 정해지지 않을 수 있다 | 문장 생성기가 한 대로 정해지는 문장만 만들고, 정해지지 않는 시작은 버림 |
| 탐지 누락 | 높은 곳에서 본 작은 차를 탐지기가 놓칠 수 있다 | 구성 2의 목표 유지 시간 |
| 계산 경쟁 | simulator와 모델이 GPU를 나눠 쓴다 | tick당 처리 시간 기록 |

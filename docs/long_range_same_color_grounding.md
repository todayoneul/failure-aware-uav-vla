# Long-range same-color grounding — 열린 문제와 backlog

44m보다 먼 시작에서, 색이 같은 물체가 여럿일 때 문장이 가리킨 것을 고르는 문제다. [canonical clean baseline](canonical_clean_baseline.md)의 범위(44m 이하) 밖에 두고 따로 보존한다. 지금 구현하는 것은 없다. 이 문서는 무엇이 관측됐는지와 다음에 시도할 후보를 적어 둔다.

**요약**

- **파랑이 아닌 목표는 먼 거리에서도 된다.** Gen-v3의 검증 시작에서 red pad·red cube는 56–70m를 포함해 12/12였다.
- **파란 목표는 멀어지면 무너진다.** 장면에 파란 물체가 넷(pad, cube, cylinder, cone)이고, 54m 이상에서 그중 지시한 것으로 간 비행은 3/9였다. 44m 이하에서의 혼동은 1/15였다.
- **데이터를 더해도 합계는 그대로였다.** 같은 색 대비 episode 199개를 더하자 "다른 파란 물체로 감"은 4 → 2로 줄고 "먼 파란 목표 앞에서 망설임"은 1 → 5로 늘었다.
- **화면이 주는 정보가 적다.** Front 화면의 수평선 부근은 기체의 팔과 프로펠러가 가리고 가운데 약 16°만 열려 있다. 70m 밖의 pad는 모델 입력에서 약 25×6px다.
- **44m 안에서도 같은 종류의 혼동이 난다.** Canonical 검증 36회 중 3회가 색이나 형태가 같은 다른 물체에서 끝났다. 먼 거리만의 문제로 떼어 낼 수 없다는 뜻이다.

## 관측

모두 [Gen-v3](aerovla_oft_gen_v3.md)의 검증 시작(학습 장면, 학습에 안 쓴 seed)과 [장거리 평가](aerovla_oft_long_range.md)의 것이다. 결과는 그대로 보존하고 다시 해석하지 않는다.

- **실패의 모양:** 정면에 보이는 먼 파란 목표로 전진을 시작했다가 몇 판단 뒤 회전으로 바뀐다. 한 번 틀어지면 목표는 팔 뒤로 들어가고 탐색으로 돌아간다(`val-5405`). 또는 가까이 있는 다른 파란 물체 앞에서 멈춘다(`val-5408`).
- **색 하나가 문제인 것이 아니다.** 빨강은 물체가 둘뿐이라 먼 거리에서도 색만으로 정해진다. 파랑은 넷이라 형태까지 봐야 하는데, 먼 거리에서는 형태가 몇 px 차이다.
- **teacher는 답을 알고 곧장 간다.** 화면에 그만한 정보가 없는 frame에도 "접근" label이 붙는다. 한 장만 보는 정책에는 일관되게 따를 수 없는 label이다.

### 44m 안에서도 같은 종류의 혼동이 난다 (2026-10-09 추가)

[Canonical 검증](canonical_clean_baseline.md#가장-큰-병목-목표-선택)(44m 이하, 새 seed 36회)에서 다른 물체에서 끝난 비행이 3회였다: blue pad 대신 blue cube(32.8m 시작), red pad 대신 red cube(39.8m 시작), blue pad 대신 red pad(28.5m 시작). 2회는 관련 물체가 먼저 보이고 지시한 pad는 화면 밖에 있던 시작이다.

- **거리만의 문제가 아니다.** 44m를 넘으면 "화면의 정보가 부족해서"가 더해지지만, 관련 물체가 먼저 보일 때 그것을 고르는 것은 가까운 거리에도 있다.
- **위의 "44m 이하에서의 혼동 1/15"는 그대로 둔다.** 그 set에는 관련 물체가 먼저 보이는 시작이 적었다.

## 왜 canonical 범위에서 뺐는가

- **Failure-Aware 실험의 기준은 clean에서 안정적이어야 한다.** 먼 거리의 작은 형태 구분은 Gaussian Blur가 가장 먼저 무너뜨릴 부분이라, clean에서도 불안정한 구간을 기준에 넣으면 Blur의 영향을 가려낼 수 없다.
- **지우거나 무시하는 것이 아니다.** 44m를 넘는 조건의 기존 결과, set L, Depot의 156개 test set(Q7·Q8의 55–90m 포함)은 그대로 있다. Depot의 156개는 아직 어떤 모델도 비행하지 않았고, 이 문제를 다시 다룰 때 쓸지 따로 정한다.

## 후보 (지금 구현하지 않음)

| 후보 | 무엇을 바꾸나 | 근거와 걱정 |
|---|---|---|
| 더 높은 탐색 고도 | 목표가 안 보이거나 멀 때 12–14m로 올라가 찾고 다가감 | 먼 지상 물체가 팔 아래로 내려와 화면 전체에서 보이고 윗면도 보인다. teacher와 비행 방식이 바뀌어 Gen-v2와 직접 비교가 어려워진다 |
| 카메라 / FOV | Front 카메라 위치를 옮기거나 시야각을 좁힘 | 가림과 해상도를 직접 푼다. 입력이 바뀌므로 지금까지의 data와 모델을 다시 만들어야 한다 |
| FiLM 등 더 강한 언어–시각 결합 | 문장으로 vision 쪽을 조절 | 계획의 진입 조건(보강 뒤에도 목표 선택이 가장 큰 병목)에 해당한다. vision 쪽 학습이 필요해 12GB에서는 구현 보류 상태다 |
| Multi-scale 시각 입력 | 화면 가운데를 확대한 crop을 함께 줌 | 먼 물체의 px를 늘린다. 입력 구조가 바뀐다 |
| 먼 거리 query twin | 55–90m에서 같은 자세·다른 명사 episode | 가장 작은 변경. 두 번째 보강이 실패의 모양만 바꾼 전례가 있다 |
| 부분 가림 뒤 되찾기 | 먼 접근 중 yaw를 강제로 틀고 되찾는 episode | 학습에 거의 없는 "조금 틀어진 뒤"를 채운다. 목표가 팔 뒤에 있으면 화면에 근거가 없어 label을 정하기 어렵다 |

## 다시 시작할 때

1. 새 seed로 44m 초과의 검증 set과 held-out set을 먼저 고정한다(L과 Gen-v3 검증 시작은 이미 설계에 쓰였다).
2. 후보 하나만 바꾼다.
3. "보였는가"와 "그쪽으로 가기 시작했는가"(grounding transition)를 따로 잰다. 색이 유일한 목표와 색이 겹치는 목표를 나눠 본다.
4. canonical baseline(44m 이하)이 나빠지지 않았는지 같은 set으로 확인한다.

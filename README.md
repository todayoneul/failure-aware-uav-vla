# UAV Vision-Language-Action Project

**문장으로 지시하는 드론을 Vision-Language-Action(VLA) 모델로 만들고, 실제 비행으로 평가하는 개인 프로젝트입니다.** Phase 1에서는 문장으로 지시한 물체를 찾아 착륙·접근하는 VLA를 학습하고 평가했고(종료), Phase 2에서는 자연어로 지정한 차량을 찾아 락온하고 일정 거리를 유지하며 따라가되, 닮은 차로 갈아타거나 놓치는 실패를 스스로 알아차리는 드론을 만듭니다(진행 중). 두 Phase는 저장소 안에서 서로 다른 폴더(`landing_vla/`, `car_follow/`)에 있습니다.

![Project AirSim에서 비행 중인 드론](landing_vla/outputs/examples/hero_drone.png)

## 2. Phase 1 요약

Phase 1은 VLA를 직접 통합하고, 다시 학습하고, 엄격하게 평가해 본 시간이었습니다. 무엇을 했고 어떤 개념을 어떤 작업으로 배웠는지는 [Phase 1 보고서](landing_vla/docs/phase1_vla_report.md)에 논문 형식으로 정리되어 있습니다. 데모, 측정 결과, 시스템, 문서 목록, 한계는 [landing_vla/README.md](landing_vla/README.md)에 있습니다.

## 3. Phase 2 진행

**주제.** 자연어로 지정한 차량("오른쪽 차선의 흰색 SUV를 따라가")을 찾아 락온하고, 차 뒤 20m·위 15m를 유지하며 따라가는 드론.

**핵심 질문.** 비슷한 차가 많고 가려짐이 있어도, 지정한 그 차를 끝까지 놓치지 않을 수 있는가.

**연구 주제.** 실패를 스스로 알아차리는 자연어 지시 드론 추적(Failure-Aware Language-Guided Aerial Target Following). 따라가던 드론이 닮은 차로 갈아타거나, 목표를 놓치거나, 명령이 모호할 때 이를 일찍 알아차리고 실패 종류에 맞게 대응합니다. 가설과 방법은 모듈형 시스템에서 입증하고, end-to-end VLA에서도 같은 실패 패턴이 나타나는지는 확장 실험으로 봅니다([연구 계획](car_follow/docs/research_plan.md)).

**구성.**

| 단계 | 하는 일 |
|---|---|
| 대상 지정 | 문장으로 화면 속 차량을 찾음 (VLM, open-vocabulary 탐지) |
| 추적 | 찾은 차량을 프레임마다 유지하고, 가려졌다 다시 나와도 같은 차로 이어 붙임 |
| 추종 | 자체 동역학 드론이 차 뒤 20m·위 15m를 지키고 카메라를 차에 맞춤. 깊이 카메라로 장애물과 시선 가림을 보면 고도를 높임 (구현 완료. end-to-end VLA 정책은 확장 실험) |
| 감시와 대응 | 닮은 차로 갈아탐, 소실, 명령 모호, 인지 저하를 알아차리고 종류별로 대응 (연구 주제, 첫 데모 뒤) |
| 화면 | 1인칭(락온 표시) + 3인칭(드론을 그려 넣은 시점) + 위에서 본 지도 (구현 완료) |

**시뮬레이터.** CARLA 0.9.16. 차량이 도로를 따라 스스로 달리고, 모든 차량의 정확한 위치를 알려 주므로 정답 data와 채점을 자동으로 만들 수 있습니다. 드론은 자체 동역학 모델(속도 명령을 0.5초 지연으로 따르는 점질량, 25m/s·6m/s²·60°/s 제한)로 동기 모드 tick마다 움직이고, 띄운 센서까지 같은 구성이면 같은 시험이 bit 단위로 재현됩니다. 비행 모델이 있는 CARLA-Air는 드론 물리가 tick을 따르지 않아 쓰지 않습니다.

![Phase 2 첫 데모: 말 입력, VLM 선택, 락온, 추종](car_follow/outputs/examples/demo1_config3_flow.gif)

*Phase 2 첫 데모(구성 3, smoke-001, 영어 지시). 문장을 받으면 VLM이 번호 붙은 후보 중 하나를 고르고, 드론이 그 차에 락온해 따라갑니다. 왼쪽은 드론 카메라, 오른쪽 위는 드론을 그려 넣은 3인칭, 오른쪽 아래는 위에서 본 지도(초록 목표, 주황 같은 차종·색의 차)입니다. 처음 2.5초는 느리게 재생합니다.*

**진행 순서.**

1. Phase 1 정리와 README 개편 (완료)
2. CARLA 설치 점검 (완료, [setup](car_follow/docs/setup.md)): uv Python 환경, CARLA 0.9.16. 차량 40대와 카메라 2–3대로 52–74 FPS. simulator는 Town03/05에서 약 2.6GB를 쓰고, Town10HD에서는 모델이 6GB를 잡아도 함께 돌아 인식 모델 예산은 약 6GB
3. 첫 데모 계획 (완료, [demo1_plan](car_follow/docs/demo1_plan.md)): Town05에서 문장으로 지정한 차를 따라가되, 같은 차종·색의 차 2–3대 사이에서 다른 차로 바뀌지 않는지 봅니다. 차량 탐지와 추적은 매 프레임, VLM은 처음 지정할 때만 씁니다. 땅 투영과 Kalman filter로 차 뒤 20m, 위 15m를 유지합니다(5단계에서 땅 투영 대신 깊이 맵으로 바꿈, 11번). 합격선은 본평가 30회에서 처음 지정 90%, 바뀜 없는 시험 90%, 목표 유지 95%, 거리 오차 3m
4. 첫 데모 구현 1단계 장면과 시험 목록 (완료, [demo1](car_follow/docs/demo1.md) 1절). Town05에 시험 63개(dev 20, pilot 3, smoke 10, 봉인한 본평가 30)를 만들었고, 각 시험은 simulator에서 시작 화면을 확인한 뒤 남겼습니다. 2단계와 3단계는 7, 8번
5. 연구 계획 (완료, [research_plan](car_follow/docs/research_plan.md)): 주제, 가설 세 개, 방해 차 세 단계(다른 차, 닮은 차, 쌍둥이), 층으로 나눈 감시기, 실패 종류별 대응, 지표, 진행 순서
6. CARLA-Air 확인 (완료, [carla_air_check](car_follow/docs/carla_air_check.md)): CARLA 0.9.16에 AirSim 쿼드로터 비행 모델을 더한 simulator입니다. 드론 비행 물리가 동기 모드 tick을 따르지 않고 실제 시간으로 돌아, 시험을 재현할 수 없으므로 쓰지 않습니다. 지금의 CARLA 0.9.16을 유지하고 드론은 자체 동역학 모델로 움직입니다.
7. 첫 데모 구현 2단계 드론 이동과 추종 제어 (완료, [demo1](car_follow/docs/demo1.md) 2절): 속도 명령을 1차 지연으로 따르는 점질량 드론과, 차 뒤 20m·위 15m를 지키는 추종 제어기입니다. dev 시험 20개의 교통을 기록해 보니 같은 구성이면 bit 단위로 재현됐습니다. 차가 고가도로에서 최고 24.5m/s로 달려 계획 초기값(20m/s, 4m/s²)으로는 5개 시험이 거리 오차 3m를 넘고, 25m/s, 6m/s²로 올리면 모두 3m 이하(평균 1.22m)라 이 값(속도 지연 0.5초, 방향 거르기 1초)으로 정했습니다
8. 첫 데모 구현 3단계 화면 (완료, [demo1](car_follow/docs/demo1.md) 3절): 1인칭 락온 화면(상자, 트랙 번호와 거리, 영어·한국어 문장), 드론을 투영해 그린 3인칭 화면, OpenDRIVE 도로 위에 모든 차를 그린 지도를 한 화면에 합쳐 영상으로 남깁니다
9. 첫 데모 구현 4단계 채점기 (완료, [demo1](car_follow/docs/demo1.md) 4.1–4.4절): 시험마다 기록한 교통을 물리를 끄고 그대로 재생해, 모든 구성과 실행이 같은 교통을 봅니다(위치 오차 0.00003m). 계획의 지표(바뀜, 목표 유지, 거리 오차)를 instance segmentation으로 계산하며, 정답으로 따라가는 구성 1은 dev 20개에서 모든 합격선을 넘었습니다. dev 5개에서는 목표가 고가도로에 5–22초 가려졌습니다
10. 가림 처리와 깊이 카메라 고도 회피 (완료, [demo1](car_follow/docs/demo1.md) 4.5–4.7절): 2초 넘는 가림이 시작되면 그 앞만 합격선에 쓰고, 뒤는 따로 보고합니다. 드론 몸체에 저해상도 깊이 카메라(160×120)를 달아, 진행 경로의 장애물이나 시선 가림이 보이면 고도를 높이고 지나간 뒤 1.5초 기다렸다 부드럽게 15m로 돌아옵니다. 깊이 맵만 입력으로 받는 모듈이라 단안 깊이 모델로 바꿀 수 있습니다. 구성 1은 그대로 합격했고, 가려진 시간은 59.8초에서 37.0초로 줄었으며, 앞의 깊이 점이 3m 안에 들어온 적이 없습니다. 속도(63–72 tick/s)와 GPU 메모리에도 무리가 없습니다
11. 첫 데모 구현 5단계 탐지기와 추적기 (완료, [demo1](car_follow/docs/demo1.md) 5절): 탐지기보다 먼저 상자에서 목표 위치를 얻는 부분을 정답 상자로 쟀습니다. 계획의 땅 평면 투영은 목표가 순환 고가도로 위에 있을 때(dev tick의 35%) 중앙값 11.3m 틀리고, 깊이 카메라로 상자 중심까지의 거리를 읽으면 땅과 고가 모두 중앙값 약 0.12m라 깊이 맵을 씁니다. 추적기는 이 위치로 세계 좌표에서 잇는 ByteTrack 방식이며, 보이는 모든 차의 정답 상자를 탐지로 넣어(완벽한 탐지) 재 보니 2초 넘는 가림 전 구간에서 바뀜 없는 시험 20/20, 목표 유지 99.97%, 거리 오차 1.49m였습니다. 실제 탐지기는 실제 드론 배포를 생각해 Apache-2.0인 RF-DETR-Small로 정하고 공통 인터페이스 뒤에 붙였습니다. 영상 한 장에 8ms, GPU 0.5GB이고, 따라가는 목표는 95%(점수 0.3) 찾지만 50m보다 먼 작은 차와 위에서 본 일부 차(회색 도로 위 회색 승합차, 주황색 Mini)는 점수가 낮아 놓칩니다(5.5절). RF-DETR와 추적기를 합친 구성 2는 dev 20개의 긴 가림 전 구간에서 바뀜 없는 시험 20/20, 목표 유지 98.7%, 거리 오차 1.52m로 합격선을 넘었고, 회색 승합차 시험에서는 탐지 공백이 1.4초까지 길어져 트랙을 지우는 1.5초 직전까지 갔습니다(5.6절)
12. 첫 데모 구현 6–7단계 VLM 처음 지정과 구성 3 평가 (완료, [demo1](car_follow/docs/demo1.md) 6–9절): RF-DETR 상자에 번호를 그려(Set-of-Mark) Apache-2.0 VLM에게 문장이 가리키는 번호를 묻고, 번호를 세 번 섞어 상자별 확률·마진·일관성을 얻습니다(모호성 감시기의 입력). zero-shot에서는 Qwen3-VL-4B(4-bit)가 가장 나았지만 VLM dev 100장 영어 79%·한국어 80%로 90%에 못 미쳤고, 틀린 답은 모두 같은 차종·색의 비슷한 차였습니다(차선·앞뒤 표현). 2B 모델을 bf16으로 시뮬레이터·탐지기와 함께 올려도 GPU 최대 10.1GB입니다. 4B 4-bit에 QLoRA를 적용하자 저장한 시작 화면에서 VLM dev 100장 99%, dev 20장 100%가 됐고, 답할 수 없는 지시는 마진 대신 log(p1/p2) 임계값으로 대부분 걸러집니다. 이어서 VLM 지정, 탐지기, 추적기, 깊이 고도 회피, 추종 제어를 한 비행으로 연결해 dev 20개, pilot 3개(2회), smoke 10개를 영어·한국어 모두 통과했습니다(처음 지정과 바뀜 없음 100%, 목표 유지 95.5–97.9%, 거리 오차 1.17–2.18m). 그 뒤 아무것도 바꾸지 않고 봉인한 본평가 30개를 열어 영어·한국어 모두 합격했습니다(처음 지정 30/30, 바뀜 없음 영어 30/30·한국어 29/30, 목표 유지 97.4%, 거리 오차 1.8m). 바뀜 1회는 회색 승합차의 위치 추정이 앞의 비슷한 차 쪽으로 끌려가 트랙이 넘어간 경우이고, 고가도로 아래 긴 가림 2건은 다시 잡지 못했습니다. 이 결과를 첫 데모의 baseline으로 둡니다

# Phase 2 연구 계획: 실패를 스스로 알아차리는 자연어 지시 드론 추적

이 문서는 Phase 2의 연구 주제, 가설, 실험 설계, 진행 순서를 정한다. 2026-11-22–23에 사용자와 선행연구 조사, 주제 후보 비교, 외부 검토 두 차례를 거쳐 정했다. [첫 데모 계획](demo1_plan.md)은 이 계획의 2단계(7절)로 그대로 이어진다. 경로는 `car_follow/` 기준이다.

## 1. 주제

**제목.** 실패를 스스로 알아차리는 자연어 지시 드론 추적 (Failure-Aware Language-Guided Aerial Target Following)

**한 문장.** 문장으로 지정한 차를 따라가는 드론이, 닮은 차로 갈아타거나 목표를 놓치거나 명령이 모호할 때 이를 일찍 알아차리고 실패 종류에 맞게 대응한다.

**프레이밍.**

1. 핵심 가설과 감시·대응 방법은 모듈형 시스템(VLM 지정 + 탐지·추적 + 추종 제어)에서 입증한다.
2. 그 위에 end-to-end VLA 백본에서도 같은 "조용한 실패" 패턴이 나타나는지 확인한다(확장 실험, 5.4절).

제목에 VLA를 넣지 않은 것은 본 실험의 주인공이 모듈형 시스템이기 때문이다. VLA를 직접 학습하는 일은 Phase 1에서 위험이 컸다(Generic Landing 1–1d, 네 단계 모두 기준 미달). 그래서 핵심 결과가 VLA 학습 성공에 묶이지 않게 했다.

**이 주제를 고른 이유.**

- **비어 있는 교차 영역.** 언어 지시 드론 추적 연구와 VLA 실패 감지 연구는 각각 활발하다. 하지만 둘을 합친 연구, 곧 비행 중에 실패를 알아차리고 대응하는 언어 지시 추적은 조사한 범위에서 찾지 못했다(2절).
- **Phase 1과 이어짐.** Phase 1의 실패는 공중 정지나 같은 색 물체 오선택으로 나타났고, 모두 모델이 모르는 채 일어났다. Phase 1에서 쓴 blur 주입, 사람 개입 모드, 봉인 평가를 그대로 이어 쓴다.
- **실제 드론으로 이어감.** 감시기와 대응은 지상 PC 추론과 PX4 offboard 구성에 붙일 수 있다. 다만 모델과 무관한 신호만 그대로 옮겨간다(5.2절).
- **규모.** 12GB GPU 하나로 할 수 있다. 감시기는 가볍고, 대형 모델 학습이 필요 없다.

## 2. 선행연구와 차별점

**표 1. 가까운 선행연구** (2026-11 기준. 아래 세 편은 초록과 공개 저장소로 직접 확인했다. 나머지 2026년 프리프린트는 원문 대조가 필요하다.)

| 연구 | 하는 일 | 우리 주제와의 차이 |
|---|---|---|
| UAV-Track VLA (2604.02241) | CARLA에서 문장으로 지정한 대상을 드론이 추적. π0.5 기반, 89만 프레임, 176개 태스크 | 실패를 사후에 세기만 하고 비행 중 감지는 없음. pitch와 roll 고정. 원거리 성공률 보행자 61.76%, 차량 약 38%. 저장소는 비어 있음(코드·가중치 없음) |
| TrackVLA (2505.23189) | 지상 로봇의 언어 지시 추적 VLA, 170만 샘플 | 가중치 미공개(비교 모델 Uni-NaVid와 벤치마크만 공개). 실패 감지 없음 |
| TrackVLA++ (2510.07134) | 공간 추론(Polar-CoT)과 목표 기억(TIM)으로 닮은 방해물과 긴 가림을 다룸 | 실패를 줄이는 쪽이고, 실패를 알아차리거나 알리지는 않음. 지상 로봇 |
| OA-VAT (2604.21453, CVPR 2026) | DINOv3 외형 프로토타입, 신뢰도를 반영한 Kalman filter, 가림 복구 플래너. Tello 실기 35 FPS | 언어 지정과 ID 전환 경보가 없음. 코드 공개(MIT) |
| DAT, DeTrack, D-VAT | 드론 능동 추적 | 언어 지정과 실패 감지 없음 |
| UAV-Flow, CognitiveDrone, DroneCATS | 문장 → 드론 비행 VLA | 추적과 실패 감지가 주제가 아님 |
| SAFE, Sentinel, VLA-FAIL, VLAConf, KnowNo | VLA 실패 감지, 신뢰도 보정, 도움 요청 | 대부분 로봇 팔 조작이 대상 |
| RefineFly / RecoverFly (2608.09467) | 항공 VLN에서 실패 사례를 학습에 다시 씀 | 비행 중 알아차림과는 다른 문제 |

**차별점.** 추적 성능 자체로 위 연구들과 겨루지 않는다. 두 가지를 보인다.

1. 조작 VLA에서 쓰는 단일 신호 감시기(내부 특징, 행동 일관성)는 드론 추적의 인지 저하는 잡는다. 하지만 닮은 차로 조용히 갈아타는 실패와 언어 모호성에서는 높은 신뢰도를 유지한다.
2. 실패 신호를 층으로 나눈 보정된 감시기와 실패 종류별 대응이, 모르고 엉뚱한 차를 따라간 시간을 줄인다. 대응에는 드론만 할 수 있는 시점 이동이 들어간다.

## 3. 연구 질문과 가설

**연구 질문.**

- **RQ1 실패 지도.** 언어 지시 드론 추적은 언제, 어떤 종류로 실패하는가?
- **RQ2 알아차림.** 비행 중 얻는 신호로 실패를 일찍 알아차리고, 오경보율을 정한 한도 안에 두며, 종류까지 구분할 수 있는가?
- **RQ3 대응.** 실패 종류별 대응이 모르고 엉뚱한 차를 따라간 시간을 줄이면서 추종 품질을 지키는가?

**가설.**

- **H1 자기 신뢰도의 맹점.** 자기 신뢰도 신호는 인지 저하와 소실에서는 떨어진다. 하지만 비슷한 차로 바뀐 뒤와 명령이 모호할 때는 높게 유지된다.
  - 자기 신뢰도 신호: 모듈형에서는 탐지 점수와 연결(association) 비용, VLA에서는 내부 특징과 행동 묶음 일관성.
  - 이 가설은 백본에 묶이지 않는다. 그래서 모듈형만으로 검증할 수 있다.
- **H2 감지 창.** 바뀜은 주로 두 차가 교차하거나 겹치거나 가려지는 순간에 일어난다.
  - 그 순간에는 운동 잔차와 연결 모호도가 잠깐 오르고, 바뀜이 끝나면 정상으로 돌아간다.
  - 바뀐 뒤에 외형 비교로 잡을 수 있는 것은 닮은 차뿐이다. 쌍둥이는 바뀐 뒤에는 외형으로 구분할 수 없다(4.2절).
- **H3 대응.** 교차가 예측될 때 미리 시야를 넓히면 쌍둥이 사이의 바뀜이 줄어든다. 실패 종류별 대응은 정지만 하는 대응보다 추종 품질을 덜 깎으면서 모르고 따라간 시간을 줄인다.

## 4. 실패 종류와 시험 설계

### 4.1 실패 종류와 정답 라벨

simulator가 모든 차의 위치와 instance pixel을 알므로, 실패가 시작된 시점(`t_fail`)을 자동으로 정할 수 있다.

**표 2. 실패 종류**

| 실패 | 내용 | 정답 라벨 |
|---|---|---|
| 모호 (시작) | 문장에 맞는 차가 0대이거나 2대 이상 | 시험 생성 때 정함 |
| 모호 (비행 중) | 문장의 단어에 맞는 차가 비행 중 새로 화면에 들어옴 | 단어에 맞는 차 중 화면에 보이는 수가 바뀐 tick |
| 바뀜 | 따라가는 차가 목표에서 다른 차로 바뀜 | 첫 데모 계획 3.2절의 정의(추적 상자 안 instance 최다 ID가 5 tick 이상 다른 차) |
| 소실 | 가림, 시야 이탈, 목표가 너무 빠름 | 목표의 보이는 pixel이 기준 아래로 떨어진 tick |
| 인지 저하 | 비, 안개, 밤, blur | 시험 조건으로 정함 |

### 4.2 방해 차의 세 단계

외형으로 해결되는 실패와, 교차 순간 감지나 미리 시야를 넓히는 대응이 꼭 필요한 실패를 나누기 위해 방해 차를 세 단계로 둔다.

**표 3. 방해 차의 단계**

| 단계 | 정의 | 바뀐 뒤 구분 수단 |
|---|---|---|
| 다른 차 | 문장의 단어(차종, 색 이름)에 맞지 않음 | 언어와 외형 |
| 닮은 차 | 단어에는 맞지만 blueprint나 RGB가 다름 | 처음 외형과의 비교, 시점 이동 뒤 VLM 재확인 |
| 쌍둥이 | 같은 blueprint에 같은 RGB | 없음. 교차 순간 감지와 예방만 가능 |

- **닮은 차 만들기.** 두 가지 방법이 있다.
  - 같은 차종 이름의 다른 blueprint를 쓴다. 목표 후보 중 SUV 3개, 쿠페 3개, 해치백 7개, 세단 5개가 해당한다. 예: Lincoln MKZ 2017과 2020처럼 거의 같은 쌍부터, Audi e-tron과 Nissan Patrol처럼 다른 쌍까지 있다.
  - 같은 blueprint를 같은 색 이름 안의 다른 RGB로 칠한다.
- **쌍둥이.** 첫 데모의 비슷한 차가 모두 쌍둥이다([demo1](demo1.md) 1.3절). 실제 도로의 택시나 같은 회사 차량에 해당한다.
- **쌍둥이에서 맞는 결과.** 쌍둥이 사이에서 바뀜이 해소되지 않으면, 사람도 정지 화면만으로는 어느 차가 원래 차인지 알 수 없다. 이때 맞는 결과는 "정체를 알 수 없음"을 알리는 것이다. 이 경우는 알아차렸지만 복구하지 못한 것으로 따로 센다(6절).
- **확인할 점.** 닮은 차의 차이가 15m 위에서 약 1,500–3,000 pixel 크기로 보일 때 실제로 구분되는지는 그 자체로 잰다. 시점을 넓히면 차가 작아지므로, 외형 구분과 시야 확보 사이의 trade-off도 함께 기록한다.

### 4.3 시험 목록

- **첫 데모 목록은 그대로 둔다.** 시험 63개와 봉인한 본평가 30개는 첫 데모의 clean 합격 판정에만 쓴다.
- **실패 시험 목록은 새로 만든다.** 실패 종류(표 2) × 방해 차 단계(표 3)를 조건으로 넣는다. 첫 데모의 지도 칸 나누기([demo1](demo1.md) 1.6절)를 그대로 쓰고 seed만 새로 정한다.
- **목록의 쓰임.**
  - dev: 개발과 조정
  - 보정: 감시기 임계값 보정 전용
  - pilot, smoke: 관문
  - 본평가: 봉인
- **보정은 시험 단위로 한다.** tick 단위 신호는 시간적으로 이어져 있어 교환 가능성 가정이 깨지기 때문이다. 그래서 보정용 시험 수를 따로 확보해야 한다. 수는 3단계에서 정한다.
- **가림.** Town05의 큰 차와 고가 아래에서 먼저 만든다. 부족하면 Town03을 더한다.

## 5. 방법

### 5.1 백본 1: 모듈형 시스템 (본 실험)

[첫 데모 계획](demo1_plan.md) 2절의 구성을 그대로 쓴다.

- VLM이 시작할 때 한 번 목표를 지정한다.
- 매 tick 차량 탐지기와 다중 객체 추적기(ByteTrack 또는 BoT-SORT)가 트랙을 유지한다.
- 땅 투영과 Kalman filter로 목표의 위치와 속도를 추정한다.
- 제한을 지키며 차 뒤 20m, 위 15m를 따라간다.

### 5.2 감시기

실패 신호를 세 층으로 나눈다. 각 신호는 실제 드론으로 옮길 수 있는지(모델과 무관한지)도 표시한다.

**표 4. 감시 신호**

| 층 | 신호 | 모델과 무관 |
|---|---|---|
| 지정 | 문장과 후보의 정합 마진(VLM 1위와 2위의 차이), 화면 속 단어 일치 차의 수 | 예 |
| 지정 | 처음 지정한 외형과의 유사도(DINOv3 등 외형 특징, OA-VAT의 프로토타입 방식) | 예 |
| 운동 | Kalman 예측 잔차(Mahalanobis 거리), 연결 모호도(연결 범위 안의 트랙 수, 1위와 2위 비용 차이) | 예 |
| 운동 | 단어 일치 차와의 교차 위험(예측 최근접 거리와 그때까지의 시간) | 예 |
| 자기 신뢰도 | 탐지 점수, 연결 비용 | 모듈형에 한함 |
| 자기 신뢰도 | VLA 내부 특징, 행동 묶음 일관성 | 아니오 (모델 종속) |

**표 5. 예상 (H1, H2). 4단계에서 실제 값으로 채운다.**

| 실패 | 지정 층 | 운동 층 | 자기 신뢰도 층 |
|---|---|---|---|
| 모호 (시작) | 잡음 | 해당 없음 (추종 전) | 못 잡음 |
| 모호 (비행 중) | 잡음 | 일부 | 못 잡음 |
| 닮은 차로 바뀜 | 바뀐 뒤 잡음 | 교차 순간만 | 못 잡음 |
| 쌍둥이로 바뀜 | 못 잡음 | 교차 순간만 | 못 잡음 |
| 소실 | 일부 | 잡음 | 잡음 |
| 인지 저하 | 일부 | 일부 | 잡음 |

**보정.** 보정 목록(4.3절)에서 시험 단위 conformal 또는 위험 통제 방식으로 임계값을 정한다. 정상 시험에서의 오경보율이 정한 한도를 넘지 않게 한다.

### 5.3 대응

**표 6. 실패 종류별 대응**

| 상황 | 대응 |
|---|---|
| 모호 (시작) | 추종을 시작하지 않고 정지 비행. 후보 번호를 보여 주며 질문 |
| 모호 (비행 중) | 추종은 계속하되 바뀜 위험을 높게 표시. 교차가 예측되면 아래 예방 대응 |
| 교차 예측 (예방) | 미리 시야를 넓힘: 상승하거나 뒤로 물러나 두 차가 화면에서 겹치지 않게 유지 |
| 닮은 차로 바뀜 의심 | 시점을 넓힌 뒤 처음 외형과 비교하고 VLM에 다시 물어 재지정 |
| 쌍둥이로 바뀜 의심, 해소 안 됨 | "정체를 알 수 없음" 선언. 정지 비행하며 보고하고, 사람에게 후보 번호를 보임 |
| 소실 | 진행 방향과 마지막 속도로 예측한 곳을 수색. 제한 시간이 지나면 안전 정지와 보고 |
| 심한 인지 저하 | 감속, 안전 고도 유지, 사람 개입 요청 (Phase 1의 takeover 모드를 이어 씀) |

### 5.4 백본 2: end-to-end VLA (확장 실험)

- **목적.** H1의 패턴(바뀐 뒤에도 자기 신뢰도가 높음)이 VLA에서도 나타나는지 확인한다. 논문의 성립 조건이 아니며, 관문으로 두지 않는다.
- **모델.** 공개된 추적 VLA를 쓸 수 없으므로(2절) 직접 학습한다. 백본 1의 정답 추종 비행을 teacher로 삼고, 시간 문맥을 넣은 경량 OFT 방식으로 12GB 안에서 학습한다.
- **"따라가는 차"의 정의.** VLA에는 명시적인 목표 트랙이 없다. 그래서 따라가는 차를 행동으로 정의한다(예: N tick 동안 드론의 추종 목표점과 가장 잘 맞는 차). 이 정의는 학습 전에 정해 고정한다.

## 6. 지표

**표 7. 지표**

| 지표 | 정의 |
|---|---|
| 모르고 엉뚱한 차를 따라간 시간 (주 지표) | `t_fail`부터 경보까지의 시간. 경보가 없으면 시험 끝까지. 시험 전체 합과 시험당 분포로 보고 |
| 감지 지연과 선행 경보 시간 | `t_fail` 뒤 경보까지의 지연. 교차 예측 경보는 교차 전에 몇 초 앞섰는지 |
| 불필요한 개입 비율 | 정상 시험에서 분당 경보·대응 횟수 |
| 복구율, 안전 전환율 | 대응 뒤 원래 목표를 다시 잡은 비율. 복구할 수 없는 경우(모호, 쌍둥이 해소 불가, 완전 소실)는 안전하게 정지·질문으로 넘어간 비율. 쌍둥이는 따로 보고 |
| 추종 품질 | 거리 오차(첫 데모 계획 3.2절), 저크, 방향 회전 속도, 화면 가운데 유지 |

**비교 대상.**

- **감시기:** 감시 없음, 자기 신뢰도만(조작 VLA 방식), 층 하나씩 뺀 것, 세 층 전체.
- **대응:** 정지만, 실패 종류별 대응.

## 7. 진행 순서

각 단계가 끝나면 결과를 사용자와 확인하고 다음 단계로 간다. 학습과 긴 실행은 사용자가 정한 뒤에 시작한다.

1. **CARLA-Air 확인 (1–2일).** 7.1절의 항목을 확인하고, simulator를 정한다. 2026-11-23에 끝냈다. 항목 2가 실패해 쓰지 않기로 했고, CARLA 0.9.16과 자체 동역학으로 간다([carla_air_check](carla_air_check.md)).
2. **첫 데모 완주.** [첫 데모 계획](demo1_plan.md) 4절 2–7단계로 모듈형 시스템의 clean 합격선을 통과시킨다.
3. **실패 시험 목록과 정답 라벨.** 4절의 목록, `t_fail` 자동 라벨, 6절 지표 계산기를 만든다.
4. **실패 지도 (RQ1, H1).** 감시 없이 백본 1을 실패 목록 dev에서 돌린다. 신호를 기록하고 표 5를 실제 값으로 채운다.
5. **감시기와 대응 (RQ2, RQ3, H2, H3).** 보정 목록으로 임계값을 정하고, 관문을 거쳐 봉인 본평가에서 비교 대상과 견준다.
6. **확장: VLA 백본.** 5.4절.
7. **후속: 실제 드론.** 지상 PC 추론과 PX4 offboard로 RC카나 사람을 따라간다. 모델과 무관한 신호만 옮기고, 임계값은 실기 정상 비행에서 다시 보정한다.

### 7.1 CARLA-Air 확인 항목

CARLA-Air(v0.1.7, CARLA 0.9.16 + AirSim 1.8.1)는 우리 CARLA 버전과 같고 쿼드로터 비행 모델을 더한다.

**표 8. 확인 항목**

| 번호 | 항목 | 필수 |
|---|---|---|
| 1 | CARLA client(0.9.16)와 AirSim client가 둘 다 연결됨 | 예 |
| 2 | 동기 모드에서 드론 물리가 `world.tick()`을 따라감(tick을 멈추면 드론도 멈춤) | 예 |
| 3 | CARLA instance segmentation 카메라를 드론 자세에 맞춰 둘 수 있고, actor ID 정답이 나옴 | 예 |
| 4 | 드론 속도 명령의 응답(지연, 최고 속도 20m/s, 가속도 4m/s² 이상) | 아니오 |
| 5 | 기존 Town05 시험이 같은 자리에 같은 모습으로 재현됨(`trials.py`) | 아니오 |
| 6 | GPU 메모리(인식 모델 약 6GB를 더할 여유), 동기 모드 속도 | 아니오 |
| 7 | 드론을 켠 상태에서 자동 주행 차 최대 44대가 안정적으로 달림. CARLA-Air FAQ는 이때 8대 이하를 권한다 | 아니오. 막히면 시험 구성을 바꿔야 함 |

- **판정.** 1–3이 모두 통과하면 CARLA-Air를 쓴다.
- 하나라도 막히면 지금의 CARLA 0.9.16을 유지하고, 드론은 간단한 자체 동역학 모델(가속도 제한과 자세 지연을 넣은 점질량 모델)로 움직인다.
- 4–6에서 걸리는 점은 기록하고 해당 단계에서 맞춘다.
- **결과 (2026-11-23).** 항목 1과 3은 통과했다. 1은 CARLA-Air에 함께 든 Python 3.10 client로만 된다.
  - 항목 2는 실패했다. AirSim 비행 물리는 `world.tick()`이 아니라 실제 시간으로 돈다. AirSim을 멈추면 CARLA의 tick도 함께 멈춘다.
  - 그래서 CARLA 0.9.16과 자체 동역학으로 간다. 자세한 내용은 [carla_air_check](carla_air_check.md)에 있다.

## 9. 위험

**표 9. 위험과 대응**

| 위험 | 대응 |
|---|---|
| CARLA-Air가 기존 코드나 정답 추출과 맞지 않음 | 7.1절 판정에 따라 CARLA 0.9.16과 자체 동역학으로 감 |
| 닮은 차의 차이가 높은 곳에서 보이지 않음 | 4.2절대로 그 자체를 결과로 기록하고, 고도와 화면 크기를 조정 |
| 보정용 시험 수 부족 | 3단계에서 보정 목록 크기를 먼저 정하고 시험 생성 |
| 첫 데모 clean 합격선을 넘지 못함 | 실패 연구를 시작하지 않고 원인 나누기(첫 데모 계획 3.4절)로 먼저 고침 |
| VLA 백본 학습이 안정되지 않음 | 확장 실험이므로 본 결과에는 영향 없음. 시도와 결과만 기록 |
| 실기에서 임계값이 맞지 않음(지연, 바람, 위치 drift) | 모델과 무관한 신호만 옮기고 실기 정상 비행으로 다시 보정 |
| 2026년 프리프린트의 주장이 원문과 다름 | 논문 작성 전에 표 1의 원문을 다시 대조 |
